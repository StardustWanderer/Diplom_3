# Diplom_3 — UI-тесты Stellar Burgers

Автоматизированные UI-тесты веб-приложения [Stellar Burgers](https://qa-stellarburgers.education-services.ru/) в рамках третьего дипломного проекта.

Тесты написаны на Java с использованием Selenium WebDriver и JUnit 4. Для организации тестового кода применяется паттерн Page Object. Проверки выполняются в Google Chrome и Яндекс Браузере. Для сбора результатов тестирования и формирования отчётов используется Allure Report.

## Технологии

- **Java 11** — язык разработки.
- **Maven** — управление зависимостями и запуск тестов.
- **JUnit 4.13.2** — тестовый фреймворк.
- **Selenium WebDriver 4.52.0** — автоматизация действий в браузере.
- **REST Assured 5.4.0** — API-запросы для подготовки и удаления тестовых пользователей.
- **Allure 2.29.0** (`allure-junit4`, `allure-rest-assured`) — сбор результатов тестирования и HTTP-взаимодействий.
- **AspectJ Weaver 1.9.22.1** — поддержка аннотаций Allure во время выполнения тестов.
- **JavaFaker 1.0.2** — генерация тестовых данных.
- **Gson 2.13.2** — библиотека для работы с JSON.
- **Lombok 1.18.46** — генерация геттеров, сеттеров и конструкторов моделей.
- **Maven Surefire Plugin 3.2.5** — запуск тестов JUnit 4.

## Требования к окружению

Перед запуском убедитесь, что установлены:

- JDK 11;
- Apache Maven;
- Google Chrome;
- Яндекс Браузер;
- соответствующий Яндекс Браузеру WebDriver;
- Allure CLI для формирования и просмотра HTML-отчётов.

В `BrowserFactory` настроен запуск двух браузеров. Для Яндекс Браузера явно указаны пути к исполняемому файлу браузера и YandexDriver. При запуске на другом компьютере эти пути необходимо при необходимости скорректировать в `BrowserFactory`.

## Запуск тестов

По умолчанию используется Google Chrome. Выбрать браузер можно через системное свойство `browser`.

### Google Chrome

```bash
mvn clean test -Dbrowser=chrome
```

### Яндекс Браузер

```bash
mvn test -Dbrowser=yandex
```

Для формирования отчётов по обоим браузерам сначала запускаются тесты в Chrome, затем в Яндекс Браузере.

**Важно:** перед вторым запуском не используйте `mvn clean`, поскольку эта команда удалит результаты первого прогона из каталога `target`.

## Отчёты Allure

Результаты двух браузерных прогонов сохраняются отдельно:

```text
target/
└── allure-results/
    ├── chrome/
    └── yandex/
```

### Просмотр отчётов

Для просмотра отчёта Google Chrome:

```bash
allure serve target/allure-results/chrome
```

Для просмотра отчёта Яндекс Браузера:

```bash
allure serve target/allure-results/yandex
```

### Сохранение HTML-отчётов

При необходимости можно сформировать отдельные HTML-отчёты для каждого браузера:

```bash
allure generate target/allure-results/chrome --clean -o target/allure-report/chrome
```

```bash
allure generate target/allure-results/yandex --clean -o target/allure-report/yandex
```

Сформированные отчёты будут находиться в:

```text
target/
└── allure-report/
    ├── chrome/
    └── yandex/
```

Allure CLI устанавливается отдельно и не является Maven-зависимостью проекта.

## Покрытие тестами

Всего реализовано 9 тестовых методов. Каждый тест запускается отдельно в Google Chrome и Яндекс Браузере.

### Регистрация пользователя

Проверяются следующие сценарии:

- успешная регистрация нового пользователя;
- отображение ошибки при попытке регистрации с паролем длиной менее 6 символов.

После успешной регистрации проверяется переход на страницу авторизации.

При вводе некорректного пароля проверяется отображение сообщения «Некорректный пароль» и отсутствие перехода на другую страницу.

### Авторизация пользователя

Проверяются четыре способа перехода к форме входа:

- вход через кнопку «Войти в аккаунт» на главной странице;
- вход через кнопку «Личный кабинет»;
- вход через ссылку «Войти» на странице регистрации;
- вход через ссылку «Войти» на странице восстановления пароля.

Для каждого сценария создаётся тестовый пользователь, после чего выполняется авторизация с его учётными данными. Результатом успешного входа должен быть переход на главную страницу приложения.

### Раздел «Конструктор»

Проверяется переключение между вкладками конструктора бургеров:

- «Булки»;
- «Соусы»;
- «Начинки».

После выбора каждой вкладки проверяется наличие CSS-класса, обозначающего её активное состояние.

## Архитектура проекта

Для организации UI-тестов используется паттерн **Page Object**. Каждый класс страницы инкапсулирует локаторы элементов и методы взаимодействия с ними.

### Page Objects

- **`BasePage`** — базовый класс страниц. Содержит `WebDriver` и явные ожидания `WebDriverWait`.
- **`MainPage`** — главная страница приложения. Содержит методы перехода к авторизации и выбора разделов конструктора.
- **`LoginPage`** — страница авторизации. Содержит методы заполнения формы входа и перехода к регистрации или восстановлению пароля.
- **`RegisterPage`** — страница регистрации. Содержит методы заполнения формы, отправки данных и проверки сообщения об ошибке пароля.
- **`ForgotPasswordPage`** — страница восстановления пароля. Содержит метод перехода к авторизации.

### Подготовка и очистка тестовых данных

Для подготовки и удаления тестовых пользователей используется REST Assured.

- В `AuthorizationTest` перед каждым тестом пользователь регистрируется через API. Полученный `accessToken` используется для удаления пользователя после завершения теста.
- В `RegistrationTest` после завершения теста выполняется попытка авторизации через API. Если регистрация прошла успешно, полученный токен используется для удаления пользователя.
- `UserData` генерирует уникальные email, имена и пароли для тестовых пользователей.
- `BaseTest` отвечает за создание WebDriver перед тестом и закрытие браузера после его завершения.

Такой подход позволяет не тратить время UI-тестов авторизации на предварительную регистрацию через интерфейс и использовать UI непосредственно для проверки сценариев входа.

## Использованные подходы

- Page Object — разделение тестовой логики и взаимодействия с элементами веб-страниц.
- Явные ожидания Selenium WebDriver — ожидание доступности и видимости элементов перед взаимодействием.
- API-подготовка тестовых данных — создание и удаление тестовых пользователей через REST Assured.
- Генерация динамических тестовых данных — создание пользователей с помощью JavaFaker.
- Allure — описание тестовых сценариев, шагов и HTTP-взаимодействий.
- Кроссбраузерное тестирование — запуск одного набора UI-тестов в Google Chrome и Яндекс Браузере.
