# Diplom_3 — UI-автотесты Stellar Burgers

Автоматизированные UI-тесты веб-приложения [Stellar Burgers](https://qa-stellarburgers.education-services.ru/) в рамках дипломного проекта.

Тесты проверяют основные пользовательские сценарии регистрации и авторизации пользователей, а также переключение разделов конструктора бургеров.

Проект написан на Java с использованием Selenium WebDriver, JUnit 4 и паттерна Page Object. Для подготовки и очистки тестовых пользователей используются REST Assured и вспомогательные API-методы. Тестовые данные генерируются с помощью JavaFaker. Для сбора результатов тестирования и формирования отчётов применяется Allure Report.

Тесты поддерживают запуск в двух браузерах: Google Chrome и Yandex Browser. Результаты выполнения сохраняются в каталоге `target/allure-results`.

## Технологии

- **Java 11** — язык разработки.
- **Maven** — управление зависимостями и запуск тестов.
- **JUnit 4.13.2** — тестовый фреймворк.
- **Selenium 4.48.0** — автоматизация взаимодействия с веб-приложением.
- **REST Assured 5.4.0** — отправка HTTP-запросов для подготовки и очистки тестовых пользователей.
- **Allure 2.29.0** — сбор результатов тестирования (`allure-junit4`, `allure-rest-assured`).
- **AspectJ Weaver 1.9.22.1** — поддержка аспектов для интеграции Allure.
- **JavaFaker 1.0.2** — генерация тестовых данных.
- **Gson 2.13.2** — поддержка работы с JSON.
- **Lombok 1.18.46** — сокращение шаблонного кода в моделях данных.
- **Maven Surefire Plugin 3.2.5** — запуск тестов в рамках Maven.

## Требования к окружению

Перед запуском убедитесь, что установлены:

- JDK 11;
- Apache Maven;
- Google Chrome и/или Yandex Browser;
- Allure CLI — для формирования и просмотра HTML-отчёта.

Для запуска тестов в Yandex Browser необходим совместимый исполняемый файл `yandexdriver.exe`. Путь к нему задаётся в `praktikum.config.BrowserFactory`.

По умолчанию используется:

```java
private static final String YANDEX_DRIVER_PATH =
        "C:/WebDriver/bin/yandexdriver.exe";
```

Если драйвер находится в другом каталоге, измените значение константы.

## Запуск тестов

Команды выполняются из корневой папки проекта.

### Google Chrome

```bash
mvn clean test -Dbrowser=chrome
```

Команда очищает результаты предыдущей сборки и запускает тесты в Chrome. Результаты Allure сохраняются в `target/allure-results`.

### Yandex Browser

После выполнения тестов в Chrome запустите:

```bash
mvn test -Dbrowser=yandex
```

Второй запуск выполняется **без параметра `clean`**, чтобы не удалять результаты предыдущего прогона.

Таким образом, результаты обоих запусков сохраняются в одном каталоге `target/allure-results`.

**Важно:** не выполняйте `mvn clean test` между двумя прогонами, иначе результаты Chrome будут удалены.

## Allure-отчёт

Allure сохраняет результаты тестирования в каталоге:

```text
target/
└── allure-results/
    ├── *-result.json
    ├── *-container.json
    └── *-attachment.*
```

В этом каталоге хранятся исходные данные для формирования отчёта: результаты тестов, информация о шагах и приложенные материалы. Это не готовый HTML-отчёт.

После выполнения тестов в обоих браузерах сформировать и открыть HTML-отчёт можно командой:

```bash
allure serve target/allure-results
```

Allure сформирует отчёт на основе сохранённых результатов и откроет его в браузере.

В проекте используется единый каталог результатов без отдельных папок для Chrome и Yandex Browser.

## Покрытие тестами

### Регистрация пользователя

Проверяются следующие сценарии:

- успешная регистрация нового пользователя;
- попытка регистрации с коротким некорректным паролем;
- отображение сообщения об ошибке при вводе пароля недопустимой длины.

### Авторизация пользователя

Проверяются следующие способы перехода к авторизации:

- кнопка «Войти в аккаунт» на главной странице;
- ссылка «Личный кабинет»;
- ссылка «Войти» на странице регистрации;
- ссылка «Войти» на странице восстановления пароля.

Для проверки успешной авторизации тестовый пользователь создаётся через API. После входа проверяется переход на главную страницу приложения.

### Конструктор бургеров

Проверяется выбор каждой вкладки конструктора:

- «Булки»;
- «Соусы»;
- «Начинки».

Каждая проверка реализована отдельным тестом. После нажатия на вкладку проверяется, что она становится активной.

Всего в проекте предусмотрено **9 UI-тестов**: четыре сценария авторизации, два сценария регистрации и три проверки конструктора.

## Назначение пакетов

- **`config`** — настройки браузеров, базовый URL приложения и пути API-эндпоинтов.
- **`data`** — генерация тестовых данных пользователей.
- **`model`** — модели данных запросов регистрации и авторизации.
- **`pages`** — Page Object-классы, содержащие локаторы и методы взаимодействия с конкретными страницами. `BasePage` содержит общие настройки WebDriver и явных ожиданий.
- **`tests`** — тестовые сценарии и проверки. `BaseTest` отвечает за создание браузера перед тестом и его закрытие после выполнения.
- **`utils`** — вспомогательные API-методы. `BaseApiMethods` содержит общие настройки REST Assured и интеграцию с Allure, а `ApiMethods` реализует операции регистрации, авторизации и удаления пользователей.

## Архитектурные решения

### Page Object

Для взаимодействия с веб-приложением используется паттерн **Page Object**. Локаторы и действия, относящиеся к конкретной странице, вынесены в отдельные классы. Тесты вызывают методы страниц вместо поиска элементов непосредственно в тестовых сценариях.

Общие настройки WebDriver и явных ожиданий вынесены в `BasePage`.

### Выбор браузера

Создание WebDriver централизовано в `BrowserFactory`. Браузер выбирается через системное свойство Maven `-Dbrowser`.

Это позволяет запускать одни и те же тестовые сценарии в Google Chrome и Yandex Browser без изменения кода тестов.

### Подготовка и очистка тестовых данных

В сценариях авторизации тестовый пользователь создаётся через API перед выполнением теста. После завершения теста выполняется попытка удалить пользователя с помощью сохранённого токена авторизации.

В сценариях регистрации очистка выполняется через API после завершения теста: сначала выполняется авторизация созданного пользователя, затем при успешном получении токена отправляется запрос на удаление.

Такой подход сокращает необходимость ручной подготовки учётных записей и помогает не оставлять тестовые данные на сервере.

### Отчётность

Для сбора результатов используется Allure. Интеграция с JUnit 4 подключена через `allure-junit4`, а интеграция с REST Assured — через `allure-rest-assured`.

Результаты тестов сохраняются в `target/allure-results`. Для просмотра подробностей выполнения сценариев используется HTML-отчёт, который можно сформировать командой `allure serve`.

## Используемые API-эндпоинты

| Метод | Эндпоинт | Назначение |
|---|---|---|
| `POST` | `/api/auth/register` | Создание тестового пользователя |
| `POST` | `/api/auth/login` | Авторизация пользователя через API при подготовке или очистке тестовых данных |
| `DELETE` | `/api/auth/user` | Удаление тестового пользователя |

Базовый URL приложения задаётся в `praktikum.config.Urls`, а пути API — в `praktikum.config.ApiEndpoints`.
